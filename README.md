# 英语实战讲评 Skill

**把试卷、参考答案和听力音频交给你的 Agent，生成一套老师能直接打开讲课的整卷 HTML 课件。**

听力可以整段听、按题听、慢速精听；阅读可以一边看原文，一边逐题讲依据、讲方法，再把值得积累的表达迁移到写作。

由 [图图 · hututu-ai](https://github.com/hututu-ai) 制作，免费开源。你可以直接使用，也可以和 Agent 讨论自己的教学习惯，修改后保存成自己的 Skill，下次换卷继续用。

## 1.0.117：Windows 自动检查抓出的问题（出在我的测试脚手架里）

把技能包发到 GitHub 之后，**线上 Windows 自动检查立刻报了错**。查下来不是课件生成的问题，而是我这轮新加的测试里有两处按 Linux/macOS 写的辅助脚本（`#!/bin/sh` 的假 ffprobe）——Windows 上没有 `/bin/sh`；另有一条断言假定"解压后保留可执行位"，Windows 没有这个概念。

- **已修**：两处"假 ffprobe"改成**给被测模块的 `subprocess.run` 打桩**——不依赖 `/bin/sh`，也不依赖可执行位；执行位断言在 Windows 上如实跳过并写明原因。技能包在 Windows 上跑自带测试不会再因为这些原因报错。
- **另一处红灯是流水线过期，这次一并修好**：线上浏览器作业跑完验收后直接打包，而打包自 1.0.44 起要求先填好 `qa-report.md` 人工复核清单。新版工作流把这一步换成"只打印清单、不代填"（清单是人的结论），并**保留**浏览器作业——它是**非阻塞**的，红绿都会留下 `browser-check.json` 产物供下载查看，因为"Windows 上点得通吗"正是这个项目最该盯的问题，不该被删掉了事。测试作业仍是唯一决定 CI 红绿的作业。
- **如实记一件未决事**：Windows 格上 `browser_check.cjs --stress` 这一步历史上就报过失败（最早见 v1.0.13 那次运行，早于本轮改动），**原因尚未定位**。所以 Windows 的浏览器交互仍算"未验证"，详见 [Windows 验收清单](docs/WINDOWS.md) 第 9 节。
- **这类错以后不用等 CI 了**：新增静态闸门，扫"随发布包发给老师的每一个 Python 文件"——凡是用了 Windows 上不存在的接口（`os.killpg`、`signal.SIGKILL`、`import pwd`…）、依赖文件执行位（`chmod` 置位、`st_mode` 取执行位），或去调 `/bin/sh`、`bash`、`*.sh` 而**没有** `os.name` 判断/`skipTest` 跳过的，**本机就失败**。反向用例逐条证明它会咬。
- **测试**：**598 项测试通过**（本机 macOS；Windows 三处修复由 CI 复核）。

## 1.0.92：读写综合的"B. 书面表达"不再被当成自定义节

上一轮修完骨架结构后继续往下看，发现一个**更隐蔽但影响更大**的问题：呈现方式（`kind_preset`）只看 `kind`，而初中卷的"读写综合"底下写的是小标题：

```
七、读写综合（本大题分为A、B两部分，共35分）
  A. 回答问题（本题共5小题，每小题2分，共10分）
  B. 书面表达（本题15分）
```

`kind` 是"读写综合"，认不出来 → 两节都落成 `custom`。后果是**写作节丢掉写作工作区**：构建不会要求 `writing_steps`/`teacher_model`，页面也不按写作渲染。

**修法**（三处实现必须同时改，否则构建说一套、页面渲染另一套）：

1. **小标题参与判断**：`kind` 认不出来时，用本节 `title`/小标题去匹配题型别名（长别名优先，避免"阅读"抢走"阅读理解"）：`B. 书面表达` → `writing`、`A. 回答问题` → `reading`、`A. 听句子选图` → `listening`。**这是卷面上的证据，不是猜**；认不出来（如"综合运用"）仍然留空给内容推断。
2. **别名表补三条口语化写法**：`回答问题/阅读回答/阅读表达` → reading、`听句子选图/听短文/听对话/听录音` → listening、`书面表达（/话题作文` → writing。三份别名表（`scripts/section_kinds.py`、`assets/lesson.html`、`scripts/browser_check.cjs`）同步，由既有的一致性测试锁住。
3. **骨架里把推断结果写成 `kind_preset`**：`scaffold.py` 生成骨架时，凡是认得出的题型都写明呈现方式（`listening`/`reading`/`seven`/`grammar`/`cloze`/`writing`），并在待办第一条要求核对；认不出的**不写**（宣告了会把它冻结成 custom）。
4. **模板指纹同步更新**（改了 `assets/lesson.html` 就必须更新 `assets/template-manifest.json` 的 `template_sha256`，否则构建会拒绝）。

实测（同一份初中卷骨架）：

```

S4 阅读理解 A    kind_preset=reading
S6 读写综合 A    kind_preset=reading    ← 回答问题
S7 配对阅读      kind_preset=seven
S8 短文填空      kind_preset=grammar
S10 读写综合 B   kind_preset=writing   带 writing_steps + teacher_model 骨架
S11 综合运用     kind_preset=(空)      认不出来就不宣告
```

- **测试**：新增 3 项（骨架按题型名+小标题宣告 `kind_preset`、认不出来时留空、三份实现的优先级顺序静态一致——"宣告 > 题型名 > 小标题别名 > 内容推断"）；更新 1 项原本断言"读写综合一律 custom"的旧期望并写明理由。

## 1.0.59：重复内容检测（省 token 里能算准的那部分）

- `cost.py` 新增重复检测（`duplicates()`），找四类：

## 1.0.48：拿一份真卷跑链路，跑出一个会渲染错界面的 bug

## 1.0.43：更新流程从"照着文档手工做"变成一条可校验的命令

## 1.0.41：普通课件不再被"多页页图"检查误判失败

## 1.0.33："无漏题"检查不再是一句空话

## 1.0.19：修好 Windows 换行导致的指纹错位

- **修掉一个只在 Windows 出现的指纹不一致**：Windows 上 `write_text` 写出 CRLF，而 `read_text` 会把 CRLF 规范化回 LF。`verify_output` 之前对**规范化后的文本**计算 `html_sha256`，而 `browser_check.cjs` 与 `package_lesson.py` 按**原始字节**计算——同一个文件在 Windows 上会得到两个不同的哈希（实测 `05c0de04…` 与 `cd388120…`），报告自相矛盾，容易让助手误判"浏览器证据已过期"而重跑甚至伪造证据。现已统一按原始字节计算。
- **边界说明**：交付打包本来就使用字节哈希，所以这个缺陷没有把老师卡死；受影响的是 `build-report.json` 里 `template_verification.html_sha256` 与浏览器报告同名却不同值。作为缺陷仍然修掉。
- **新增两条回归测试**：一条模拟 Windows 的 CRLF 产物并断言哈希等于原始字节；一条静态扫描全部脚本，禁止对 `read_text` 的结果做 sha256。全量审计确认所有哈希都基于字节。

- **听力优先原文对齐（WhisperX）**：有听力原文时默认走 [WhisperX 工作流](references/whisperx-workflow.md)，由 `scripts/align_whisperx.py` 在已核对的时间窗内对齐，保留原文与对齐文字，并绑定音频、计划与脚本指纹。异常时间不会被标成已完成，而是返回 `aligned_review_required` 交给老师抽查；已有同源 SRT/VTT/带时间 JSON 直接复用，不重复安装或转写。whisper.cpp 仍是已有环境可用的候选路径，不要求两套都装。
- **生成前功能多选**：新增「批注」「查词」两个可选开关，与课堂工具、速对答案、篇章精读、写作迁移、文化背景一起共七项。每次生成前用宿主真正的多选控件问一次；宿主只支持单选时改成编号清单，允许一次回复多个编号，不预选全部，也不逐项问七轮。
- **文化背景必须可溯源**：选中才写，并按 [本篇文化背景规范](references/culture-background.md) 执行：原文切入 → 已查证背景 → 回到本篇的理解与课堂讲述。新数据必须填写 `reading_connection` 与来源 `supports` 并完成语义复核；测试占位卡、通用百科拼贴与民族性格概括不通过校验。
- **备课编辑就地输入**：展开解析后可直接点击题型、解题步骤、答案依据或方法迁移就地修改，失焦保存、Esc 取消；答案、定位依据等复杂字段仍在题旁“修改讲解”里改，原参考答案保留并可恢复。
- **校验与示例同步**：文化背景校验独立为 `scripts/culture.py` 并由构建调用；示例计划与浏览器测试夹具同步为七项功能结构。

具体说明：[教师选项与功能多选](references/teacher-options.md) · [WhisperX 工作流](references/whisperx-workflow.md) · [本篇文化背景规范](references/culture-background.md)。可复核记录见 [本版验证记录](docs/VERIFICATION.md)。

### FFmpeg 下载卡住怎么办？

新版先检查电脑或 Agent 已有的工具，不要求每次重新安装。遇到 GitHub/代理 502，不无限换源等待；安装尝试设置总时限，失败后继续已选文字板块，并询问老师延长准备或选择替代方案；经老师接受后，听力可接完整原音并明确标注未分段。等环境补齐后只补听力，不重做整卷。详见 [下载失败处理](references/dependency-recovery.md)。

## 第一次来，先看这三句话

1. **Skill 是交给 AI 助手使用的备课流程。** 需要一个支持安装技能、读取文件和运行工具的 Agent；普通聊天窗口能否使用，取决于它是否具备这些能力。

3. **生成后拿到的是课件文件。** 用浏览器打开 `index.html` 上课；基础讲评不需要给网页另填 AI API，完整课件文件夹可以离线带到教室。

## 1.3.2：听力一定接入、答案可溯源、Windows 与手机可用、生成更快

这一版集中处理老师反馈最多的四件事，并把生成流程本身提速。

**听力不会再"消失"**：音频由构建器按章节号和题号自动接线；完整自动分段、静音自动分段（页面标「边界待核对」）、整卷原音（页面标「未分段」）三种方式按电脑环境自动选择，页面写明本次用的是哪一种。老师没提供音频时显示缺项说明，既没有音频也没有说明会阻止构建。转写与音频用 SHA256 互相绑定。

**答案保留出处**：答案先由脚本从你提供的答案原件解析成题号—答案对照表，再逐题记录页码位置，生成课件时三处对照一致才输出；对不上会停止并列出具体题号。逐题审计还会检查「正确选项与证据句有没有共同实词」、完形答案分布异常、答案来源未写页码等情况并列出待核项，找不到出处的答案标为待核或推定。

**Windows 与手机**：Windows 上按实际名称查找转写程序（whisper-cli / whisper / main），中文报错不再中断脚本，环境自检给出 winget / scoop / choco 安装命令与模型位置，跨盘符路径自动处理。手机端补齐老浏览器缺失的 API（Array.at、matchAll、flatMap、Object.fromEntries、dialog.showModal），关闭的弹窗不再铺满页面；页面打不开时会显示中文提示，指引换浏览器、整份文件夹一起拷贝、在微信里选「用其他应用打开」。建议 iOS 14.5 / Android Chrome 88 以上，投屏上课仍建议用电脑浏览器。

**生成更快**：校验一次列全所有问题（按节、按题隔离），不再改一个跑一遍；新增分节并行写作（整卷拆成每节一个文件，可同时写不同节，写完合并）；长句引用可只写字符范围，由脚本自动填成逐字引文；新增快速档，只要求讲课必需项，精读项后补；已有与本录音匹配的带时间转写时可跳过 ASR；仅有纸质听力原文时仍需获取时间对应关系。已有转写可复用、裁剪可续跑。

## 会不会生成和视频里完全不同的课件？

**同版本使用同一套完整模板和交互代码，Agent 负责填入新试卷的内容。** 默认不能重画界面、删减功能或只做简化网页。原卷包含的题型必须完整保留；只有阅读材料时，不会凭空编一套听力。

为避免“看起来有按钮，点进去没有内容”，构建还会检查听力精听与每题录音、词句精讲、篇章结构、写作迁移、七选五线索、语法知识卡等对应数据。缺少必需内容会停止构建，要求 Agent 补齐。

成品的 `build-report.json` 应包含 `template_verification.status: passed` 和 `feature_coverage.status: passed`。前者核对网页是否使用完整原版模板，后者核对相关功能是否有数据。Agent 还必须实际打开课件，检查播放、定位、解析、批注等交互。这些检查保证的是模板与功能交付，不代替对原卷文字、答案和音频切点的核对。

**完整安装包、可运行工具的 Agent 和完整材料缺一不可。** 如果某个平台不能运行构建脚本，应明确报告环境问题，不能换成另一个简化页面冒充本 Skill 成品。当前已验证本地构建和 Chrome 浏览器；其他 Agent 平台仍需实际验证。

自 1.1.1 起默认只输出教师讲评课件，已移除“资料”中的学生学案入口及默认学案生成。教师示范、课堂追问与写作迁移保留。

可以把这句话一并发给 Agent：

```text
使用英语实战讲评 Skill 的随包固定模板和 scripts/build.py 生成完整教师课件，不重新设计或删减功能。先确认本次整卷或指定板块范围，再按原卷核对该范围的题号与题型，补齐每项功能数据，运行 scripts/verify_output.py 并实际打开浏览器验收。请提供 index.html、完整媒体文件、exam.json、build-report.json 和打包 ZIP；如果检查失败，先修复，不要交付替代网页。
```

## 第四步：打开课件，上课前过一遍

生成完成后通常会得到：

```text
本次试卷讲评/
├── index.html          教师讲评课件：用浏览器打开
├── exam.json           可编辑内容：交给 Agent 修改
```

`build-report.json` 由构建脚本输出；`qa-report.md` 由 `scripts/qa_report.py init OUTPUT` 生成待填清单、填好后用 `check` 校验，逐条记录原件比对、解析自洽、听力边界、浏览器实际操作与未完成项。有结构检查不等于已经证明所有讲解正确；条目空着或写着"待填"会被 `check` 和打包一起拒绝。

3. 听力先看题、听音，再展开“原文与精听”；阅读左边原文、右边讲评，需要时展开原文通读。
4. 上课前先看一下准备讲的答案与片段，按本班情况确定哪些词句和方法要多讲。
5. 换电脑时复制**整个课件文件夹**，保留音频和图片。不要只拿走一个 HTML。

课堂批注等记录保存在浏览器中。离开教室或更换电脑前，在“资料”里导出课堂记录；下次打开同一套课件后导入。浏览器清理数据、换浏览器或换文件位置时，导出的记录能帮助恢复。

## 常见疑问，先回答四个

**需要额外填写 AI API 吗？**

这套 Skill 使用运行它的 Agent 的能力。生成后的基础讲评不要求老师再给网页接一套 AI API。Skill 免费开源；Agent 平台本身的额度或费用按各自规则计算。

**双击 HTML 就能上传新试卷生成吗？**

HTML 是生成好的课件。要制作下一套卷子，回到 Agent 中提供新材料，再调用 Skill。

**离线能用到什么程度？**

已经生成并打包的原文、解析、译文、本地听力、基础词典和课堂工具可离线使用。在线词典扩展需要网络；系统朗读是否可离线，取决于当前设备的语音包。

**里面包含整本五三或其他教辅吗？**

不包含。你可以提供自己有权使用的教研资料，让 Agent 按本卷考点参考、核对和整理成就地知识卡。公开包提供模板、工具与有明确许可的基础词库，不附赠商业教辅或真实考试材料。

更多情况见 [常见问题](docs/FAQ.md)。

## 生成后，怎样改成适合自己班的课件

课件默认是简洁的课堂展示。顶部点 **备课编辑**，才显示修改控件；完成后再点一次即可回到讲课。

- **调整词句**：打开本节“词句”，在生词速查、重点词汇或句子精讲中修改释义、原句、主干或教师备注。不准备讲的条目选择“课堂隐藏”，需要时恢复；还可以补充条目。原句需来自所选段落。
- **保留语境**：划选原文，点“收入词句”，补充本篇释义后保存。段落位置和原句一起留下；同一个词在不同段落的用法可以分别保留。原有词旁窗口中的“积累”也会保留来源语境。
- **修订讲解**：开启备课编辑后，题目下方有“修改讲解”。可改解题说明、步骤、迁移方法和原文依据，标准答案保留原样。支持查看原解析和恢复原始讲解。
- **精确标句**：原文划选后可高亮、画下划线或波浪线、换色、记一笔；点已有标记可修改或移除。箭头、矩形等自由板书仍在原来的“批注”里。
- **投影逐题讲**：先选“逐题看”，勾选“本题下方显示相关原文”。题目下面显示所有相关段落，点“回看全文”恢复左右栏。不用同时维护两份原文。
- **导出词句**：在“词句”窗口导出本节CSV，包含当前未隐藏的词句、原句、位置和教师备注，可用表格软件继续整理。

这些修订和标记保存在当前浏览器，并随原来的 **课堂记录导出／导入** 一起携带。换电脑时带上完整课件文件夹和课堂记录；直接复制原来的 HTML 文件不包含只保存在浏览器中的课堂修改。原始 `exam.json` 不会因浏览器操作自动改写。

以上功能无需额外AI API。补充新条目是在课件里直接编辑；需要AI重新分析内容时，仍可把要求交给运行Skill的Agent。


## 新任务的执行顺序（WhisperX 接入）

安装 Skill 后，先提供试卷、参考答案及有则提供的听力音频。Agent 快速盘点材料，再询问“独立听力精听 / 整卷 / 指定板块”以及可选扩展。只做阅读无需安装语音模型；有同源时间轴直接复用；需要听力对齐时才准备 WhisperX。模型、英语分句资源准备好后先跑小样，再处理正式材料。已有听力原文先核对实际读法，没有原文才先转写；不要求老师申请额外 API。

完整流程见 [教师选项](references/teacher-options.md) 和 [WhisperX 工作流](references/whisperx-workflow.md)。新接口 `scripts/align_whisperx.py` 保留原文与对齐文字，绑定音频与计划指纹，并拒绝把异常时间标为已完成；音频切片仍需要语境与播放验收。

### 文化背景如何生成

勾选后，Agent 从本篇的具体人物、表达与社会文化现象出发查证资料，按“原文切入 → 背景解读 → 回到本篇的理解”编写，并提供可直接讲述的说明与来源。不是每篇自动套通用知识；没有必要背景时不凑数。结构检查不能代替对来源与内容的复核。
