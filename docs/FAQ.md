# 常见问题

## Skill 包、源码 ZIP、课件包有什么区别？

| 你拿到的文件 | 用来做什么 | 怎么使用 |
|---|---|---|
| Skill 安装包 | 让 AI 按固定流程生成新课件 | 导入支持 Skill 的 AI 助手，保留其中的说明、模板和脚本 |
| GitHub 源码 ZIP | 项目源文件，可能带有仓库名称的外层目录 | 解压后由助手识别 `SKILL.md` 所在目录；是否需重新打包取决于宿主平台 |
| 已生成的课件包 | 讲解某一份具体试卷 | 完整解压，打开里面的 `index.html`；不需要导入技能管理页 |

如果只是想在教室播放已经生成好的课件，**浏览器和完整课件文件夹就够了**。只有换试卷重新生成时，才需要运行 Skill 的 AI 助手和生成环境。

## 我打开 HTML，为什么看到的是代码？

你可能用文本编辑器打开了它。右键文件，选择“打开方式”，改用浏览器；也可以把文件拖进浏览器窗口。

检查打开的是生成结果中的 `index.html`，而非仓库里的 `assets/lesson.html`。后者是等待注入题目数据的模板，不能当成完整课件。若文件实际叫 `index.html.txt`，让助手检查真实扩展名和保存内容，不要仅凭显示名称判断。

还没解压 ZIP 的话，先解压整个课件包再打开。

## 为什么听力不播放，或者换电脑就没有声音了？

1.0.6 默认内嵌听力，单独复制 HTML 仍可播放；下载不完整、平台限制文件体积或预览环境拦截媒体时，先完整下载再用系统浏览器打开。若生成时使用了 `--audio-mode folder`，则必须完整解压并保留 audio/。

检查系统音量、浏览器标签页是否静音，并手动点击播放。构建报告中的 `audio_delivery.mode` 区分 embedded 与 folder；旧版本的 `audio_embedded=true` 曾只代表存在音频路径，不能证明声音已写入 HTML。更新 Skill 后重新构建才能改变旧课件的交付方式。

原卷听力播放器使用实际音频文件；单词发音使用系统语音或可选词典录音。两者故障原因可能不同。

如果能够播放，但“重听关键句”总是从头开始，让助手按 [环境准备](SETUP.md) 使用项目自带的预览服务，检查音频时间定位。不要仅因为播放条出现，就认为逐句定位已经验证。

## 我只拿一个 HTML 发给同事可以吗？

默认内嵌模式下，单个 HTML 含听力；有原卷页图或需要后续编辑时，请发**完整课件 ZIP**。同事解压后打开 `index.html`，目录中的音频和图片保持相对位置。

页面中的本机预览地址只在启动它的电脑上有效。不要把 `http://127.0.0.1:…` 当成公开分享链接发给同事。

## 生成中断了，要全部重来吗？

通常可以从已有文件继续，但要让助手确认哪些是真正完成的。优先回到原任务，保留已经提供的附件、内容数据和工作文件，发送：

```text
请继续生成这份英语讲评课件。先查看本任务的材料和已经保存的文件，列出已完成与未完成的部分，检查是否存在半成品，再从可复用的步骤继续。
保留已经核对的原文、解析和音频，不要无理由从头重做，也不要用简化内容替代未完成部分。续跑后重新检查受影响的题目、音频和课堂操作，完成完整交付。
```

若是平台额度用完、下载失败或权限不足，先处理对应问题。耗时受材料页数、扫描质量、录音时长、模型和电脑影响，没有固定完成时间。自动流程也不能省略核对。

**时间主要花在哪里**：脚本本身很快（10 多节的整卷，构建与核验通常在 1 秒内），大头是助手写教学解析、以及**返工**。所以想快、想省额度，最有效的三件事是：

1. 一开始就把范围说清（只要听力 / 只要某个板块，不要的板块不写也不生成）；
2. 一次把材料给全（原卷、答案、音频、图片），不要边做边补；
3. 构建报错时看那句 `共 N 处问题，一次改完再重跑`——1.0.45 起报错会把本节问题一次列全、用中文写出实际值（例如"实际出现 1 次，条目写的是 9"），按清单一次改完，不要改一条就重跑一次。

## 没有答案，或者没有听力，也能做吗？

可以先做材料足够的部分。

- **没有参考答案**： 可以要求助手独立解题，但应标明“推定答案”和依据；拿到官方答案后再核对，不能冒充已经核过官方答案。
- **没有听力音频**： 可以完成其他题型；听力题和文字材料可保留，但不能声称已完成原音切段。浏览器朗读也不能冒充原卷听力。
- **有音频、没有听力原文**： 可从实际音频转写，并核对题目、边界和低置信度词句。
- **缺页或版本冲突**： 让助手指出具体缺项，完成不受影响的部分；补齐材料后继续。

## 一定要填写 AI API 吗？免费分享是不是完全不花钱？

**课件不要求老师另外填写模型 API。** 生成阶段使用你正在运行的 AI 助手；Skill 提供备课流程、模板和工具，不能单独替代模型服务。

项目免费分享。你所使用的 AI 平台可能有免费额度、订阅或计费规则，由平台决定。未来若自行选择付费识别或转写服务，也需按该服务规则使用，这些不属于课件上课的必需接口。

## 离线时哪些功能能用？

完整文件夹已经下载到电脑后，内置的原文、题目、讲解、逐段译文、本地听力、批注和课堂工具可以离线使用。**词库默认只收录本篇出现的词**：查这些词离线可用；查本篇以外的生词需要联网，或者在生成时用 `--dictionary-scope full` 把整本词库内联进课件（体积会明显变大）。

在线词典补充释义和网上录音需要网络。系统合成发音能否离线使用，取决于设备是否有相应英语声库；选择“英音”或“美音”不代表所有电脑都已经安装这两种声音。

离线使用成品课件，与离线调用 AI 生成新课件是两回事。

## 点单词出来的意思，为什么与在线词典不完全一样？

课件优先展示生成阶段整理的**本篇语境义**，再提供通用词典义。例如同一个词在这一段是“刻薄的”，在其他句子里可能是“意味着”。通用词典会列出多个用法，不能直接决定本句应该选哪一个。

未事先编写语境义的词会显示可用的通用释义；它不等于运行时已经让 AI 分析过当前句子。若某词确实值得重点讲，告诉助手它在哪一节、哪一句，要求补充并核对语境讲解后再生成。

“联网补充英文释义”从在线词典取得额外信息，不是实时 AI 教研助手。接口没有收录、网络不可达或录音缺失时，本篇词条的内置释义仍可用（本篇以外的词需联网或改用 `--dictionary-scope full`）。词典录音与系统合成朗读会分别标示。

## 课件会给老师布置练习吗？

主课件面向教师备课和投屏讲评：老师控制答案揭示、查看示范改写、记录典型错误。原卷题目完整保留，便于课堂讲解。


## 为什么“全部题目”没有把所有解析一起打开？

“逐题看／全部题目”决定浏览范围。答案和解析仍按题揭示，同一节最多展开一道题的解析，方便老师控制讲评进度。

点选选项先记录课堂选择；老师点击“答案与解析”才揭示答案。这样可以先讨论，再核对。

## 怎么保存批注和上次讲到哪里？

同一浏览器会尝试保存课堂状态。要换电脑、换浏览器或更新课件，请先导出“课堂记录”，不要只依赖浏览器缓存。记录包括相关选择、文字笔记、笔迹、待复讲标记和界面设置。

将记录文件与对应课件一起保存，换设备后在同一份课件中导入。不同试卷不要混用记录；题号和段落结构发生变化后，也应让助手检查恢复结果。

## 我想改颜色、讲解习惯或功能，怎样避免越改越乱？

先让助手保留当前稳定版，再在新副本中改。描述具体课堂场景，比单说“更好看”“更智能”容易落实。

例如：“我讲阅读先看全文，默认展开原文；进入讲题时恢复左右对照。”“写作迁移每篇挑两三句，讲透表达效果，主界面不放学生作答框。”

查看结果，确认满意后，再要求把这些可复用习惯更新到个人 Skill。不要把当前试卷的专用答案、固定题号或一次性布局问题写成所有试卷的默认规则。更新公开版本前，备份你的个人 Skill、课件和课堂记录，避免直接覆盖个性化调整。

## 为什么我的电脑安装失败，但别人可以？

可能是宿主的 Skill 导入格式、文件执行权限、Python/音频依赖或网络环境不同。先让助手按 [SETUP.md](SETUP.md) 做检查，并提供准确错误信息。

WorkBuddy 官方提供本地技能包导入入口，但本项目尚未完成该平台的整套实机验收。其他未标明验收的宿主和系统也应先做小样例测试；不要把“支持 Skill”理解成所有配套工具已经预装。

## GitHub 打不开、又没有梯子，还能装吗？

**通常能装。** 安装只需要"这台能跑脚本的电脑/助手拿到完整 ZIP"，**下载可以发生在别的地方**——这是关键区别。

- **要区分三件事**（很多人把第 2、3 件当成第 1 件）：`github.com` 的仓库页面、`raw.githubusercontent.com`（逐个抓文件用）、以及 **Release 里的 ZIP 下载**（走对象存储域名）。在部分网络下，第 1 个能打开，第 2、3 个却经常超时或打不开——所以"能打开 GitHub 网页"不等于"能下完整包"。这跟运营商、地区、时段都有关，**以你所在网络实测为准**：让助手跑一次 `py -3 scripts\host_probe.py --network`，它会如实打印四条安装路径的可用性。
- **发布 ZIP 大约 2MB**（本版 1.9MB）：微信、邮件、网盘都能转发，所以"换一台能上网的设备下载再传过来"这一条通常最省事。
- **没有梯子时最稳的一条**：在**任何**能上网的地方拿到发布 ZIP（手机流量、家里别的网络、同事的电脑、或让助手在能访问的环境下载），再通过微信/网盘/邮箱把 ZIP 传到这台电脑，**作为附件发给助手**，让它在本地解压安装。这条路绕开了这台机器的网络限制。
- **其次**：宿主能开网页但 shell 不能下载时，让助手用一条命令抓（**不要手工逐个抓**）：`py -3 scripts\fetch_package.py --base https://raw.githubusercontent.com/hututu-ai/english-exam-studio/main --out 临时目录`——它按 `install-manifest.json` 下载每个文件并逐个核对 SHA256，缺文件、哈希不符、越界路径都会如实列出；`raw` 打不开时把 `--base` 换成 `https://cdn.jsdelivr.net/gh/hututu-ai/english-exam-studio@main`（第三方 CDN，通常更好打开；哈希一致只证明传输没损坏，来源可信仍需官方 `SHA256SUMS.txt` 核对官方 ZIP）。抓完必须 `py -3 scripts\check_install.py` 到 `complete`。
- **最不稳**：`git clone`。沙盒常拦它的 TLS 握手，**不要反复重试**。
- **不要做的事**：用来路不明的第三方"GitHub 加速镜像"替换官方包，或把零散文件（只有 `SKILL.md`、`VERSION` 之类）拼成一个"技能"。这两条都会让包与官方不一致，指纹核对也会失败。优先用官方 Release 与官方提供的导入入口。
- **判断标准不变**：只有 `check_install.py` 显示 `complete` 才算装上；VERSION 相同、网页能打开、助手说"已安装"都不算。

## 助手说"沙盒限制 / 网络受限"，这是什么意思？

**这不是这个 Skill 的限制，也不是脚本坏了**，而是 AI 助手所在平台为了保护你和平台的安全，给它加的执行隔离。常见的几种（我们实测过其中的 TLS 那条）：

| 限制 | 表现 | 怎么继续 |
| --- | --- | --- |
| 网络出口白名单 | 网页能抓，`git clone` 或下载二进制报 TLS/超时 | 改用"附件上传 ZIP"；或让助手把网页能读到的内容取回来 |
| 只能读写工作目录 | 写系统目录、改 PATH、装软件被拒 | 把工作目录设在可写位置；依赖缺失时按实际降级，不硬装 |
| 不给执行 shell/Python | 构建、校验、打包都跑不起来 | 让助手明确说明"当前环境跑不了脚本"，只做能做的部分，不拿一段 HTML 冒充成品 |
| 预览限制脚本/媒体/弹窗 | 预览里打不开、白屏、音频不出声 | 下载完整 ZIP，解压后用系统 Chrome/Edge 打开 |
| 云端容器而非你的电脑 | 在"云电脑"里装好了，你本机还是没有 | 说清哪台机器上装、哪台机器上用；路径与权限是两回事 |

**每个人的限制为什么不一样**：取决于所用助手/平台、是否企业或学校统一配置的策略、以及助手实际运行在哪台机器（云端容器 ≠ 你的电脑）。所以"别人能装、我这台不行"通常不是 Skill 的问题，而是通道不同。

正确做法是**换一条能用的通道，并把被挡住的那一步如实说清楚**（下载受限、不能写盘、不能执行、不能开浏览器），而不是绕过限制、无限重试，或用 `.sh` 脚本、零散文件拼一个"看起来装上了"的版本。

要收集"这台机器到底能做什么"的报告时，Windows 老师可以**双击技能包里的 `一键体检.bat`**（不装东西、不改设置，跑完把打印出的 `smoke-report-*.zip` 发回即可）。

## 可以怎样反馈问题？

在 [GitHub Issues](https://github.com/hututu-ai/english-exam-studio/issues) 提交反馈，建议说明：

- 系统、浏览器、使用的 AI 助手以及 Skill 版本。
- 发生在哪一步、哪一节或哪一道题。
- 做了什么操作、期待什么结果、实际出现什么情况。
- 必要截图和错误信息；涉及音频时说明整段、逐题还是关键句复听。

截图和附件先去掉学生姓名、成绩、账号、密钥和私人路径。无需把整份考试材料公开上传；可以用能复现问题的简短自写材料或局部说明。功能建议尽量描述真实课堂情境，便于判断应新增、合并还是简化入口。

## 我装的是旧版，怎么更新？

Skill 是电脑上的文件夹，不会自动升级，需要发布新版本后手动换一次。当前最新版本是 **1.0.5**。

最省事的做法是让助手更新：把「请把 english-exam-studio 更新到最新版：先备份我当前的技能目录，再从 https://github.com/hututu-ai/english-exam-studio/releases/latest 下载最新 ZIP 替换旧文件并保留我的笔记文件，最后告诉我版本变化」发给它就够了。也可以自己从 [最新版本](https://github.com/hututu-ai/english-exam-studio/releases/latest) 下载 `english-exam-studio.zip`，在平台的已安装技能里覆盖导入。

更新前请备份技能目录。更新不会影响你已经生成的课件，课堂记录也存在浏览器里，与 Skill 版本无关；但你自己改过的 `SKILL.md`、模板或脚本会被新版覆盖。完整步骤见 [UPDATE.md](UPDATE.md)。想确认自己是哪个版本，看技能目录里的 `VERSION`，或让助手运行 `scripts/check_update.py`。

## 不同 AI 助手能力不一样，会不会影响生成？

会。不同宿主在读取完整技能包、读附件、写文件、执行 Python、多选控件、浏览器验收和下载依赖上差别很大，同一份 Skill 不见得每项都能跑。开工前该问清的能力和缺能力时的回退，见 [宿主能力与回退](../references/host-compatibility.md)。

一条规则：**缺哪项能力，助手就直说缺哪项，并交付明确标注的"待验收"版本，不能把没做到的步骤说成已完成。**
