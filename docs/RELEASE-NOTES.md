## 1.0.117：Windows 自动检查抓出的问题（出在我的测试脚手架里）

- 这一版把技能包正式发到 GitHub 后，**线上 Windows 自动检查立刻报错**。查下来不是课件生成的问题，而是我新加的测试里有两处按 Linux/macOS 写的辅助脚本（`#!/bin/sh` 的假 ffprobe），Windows 上没有 `/bin/sh` 就必然失败；另外一条断言假定"解压后保留可执行位"，Windows 没有这个概念。
- 现在改成跨平台写法：**不造"假的 ffprobe 可执行文件"**，而是让测试直接替换被测代码调用系统命令的入口——不依赖 `/bin/sh`，也不依赖可执行位；执行位那条断言在 Windows 上如实跳过并写明原因。技能包在 Windows 上跑自带测试不会再因为这些原因报错。
- 并且加了一道**静态检查**：以后凡是"在 macOS 上能跑、到 Windows 上必炸"的写法（用了 Windows 上不存在的系统接口、依赖文件的可执行位、去调 `/bin/sh` 或 `.sh` 脚本却没做平台判断），在开发机上就会直接报错，不用等发布后 CI 才发现。发布包里解压出来的每一个 Python 文件都在检查范围内。
- 又补了 **34 条**"改松了也不会有人发现"的检查测试：例如"引用必须落在完整词上""切点上的引文必须与那段转写吻合，不能改音频去迁就引文""压缩包里的路径不安全就拒绝解压""备份目录不能覆盖技能目录""没有先问老师就不能开始生成"。这些检查以前只写在代码里，没有任何测试证明它们真的会拦住人；现在每条都有一个"故意做错、必须被拦"的用例，并且加了一道守卫：以后新增或改写的报错说明必须在测试里出现，否则开发机上就会失败。
- 另一处**浏览器自动检查**的红灯是"发布流水线文件过期"（它没填写人工复核清单就直接打包，而打包从 1.0.44 起要求填好清单）。现在流水线不再代填清单——清单是人的结论，它只把清单打印出来给人看；同时**保留**浏览器自动检查，不阻塞但红绿都留报告可查。另外如实说明：Windows 上的浏览器自动检查历史上有一处失败（早于本次改动）**尚未定位**，所以 Windows 上的浏览器交互仍算"未验证"，不会写成已通过。
- 另外把"浏览器验收失败时说不清卡在哪"改掉了：报告现在会写明**跑到第几项、卡在哪个阶段、跑了多久、用的哪版 Node**，超时上限也能调（`BROWSER_CHECK_TIMEOUT`，默认 180 秒）。机器慢的老师可以把上限放宽，但请先把失败信息原样发回——别把真的卡死当成"只是慢"。
- 你不需要做任何事；照旧用发布包即可。

## 1.0.103：引用范围会产出"半截词"；把计划文件当试卷传会漏英文报错

- 写解析时，长引文可以只写"第几个字到第几个字"，由脚本回填，省掉逐字抄写。但**新发现**：如果范围切在单词中间（例如把 `museum` 切成 `' op'`），回填会照做，而且**所有检查都说没问题**——检查只看"这段话在原文里出现过"，半截词也算出现过。现在回填会直接拒绝并告诉你切到了词中间，已经填好的半截词也会被点名（可跑 `python3 scripts/quotes.py check WORK/exam.json` 复查）。

## 1.0.102：在 Windows 上跑完的体检报告，以前可能被判成"不是在 Windows 上跑的"

- 你（或我）在 Windows 上跑 `一键体检.bat` / `smoke_report.py` 之后，会生成一份报告发回判读。判读脚本以前**只从两处找平台信息**，而这两处在真实报告里都不一定在：报告本身没写平台字段，而另一份宿主探测文件在"宿主能力"这一步失败时根本不会生成。
- 结果：**一台真的在 Windows 上跑出来的报告，可能被判成"本次报告来自 unknown，不是 Windows"**，Windows 验收永远无法确认。现在判读会依次看报告里的平台、宿主探测、以及报告自带的系统字段，并且报告本身也会写明平台；实在拿不到平台信息时，会如实说"无法判断"，而不是当成"不是 Windows"。
- 你不需要做任何事。**如果你之前跑过 Windows 体检**，请用这一版重新跑一次 `一键体检.bat`，报告就能被正确判读了。

## 1.0.101：答案对照以前会误判"多选/变体"写法

- 核对答案时，工具会把成品答案和答案原件逐题比对。以前这条检查在两处各写了一套逻辑，结果**同一份数据两种判决**：原件把多选题解析成 `AB`，成品照规范写成 `["A","B"]` 会被判成"不一致"；成品写成 `"AB"` 又会被另一处判成"不在选项里"。两种都是**误拦**。
- 现在两处共用同一套比较：既认原有的"变体数组"写法，也认 `AB` 与 `["A","B"]` 是同一次多选。真正不一致的（例如原件 `AB`、成品只写 `A`，或成品多写一个 `C`）**照旧拦住**。
- 多字母答案会同时列进**待核项**：页面目前会把 A、B 各自判为正确，所以真正的多选题还没有学生端判分——这条限制现在写在 `references/schema.md` 里，不假装支持。
- 你不需要做任何事；如果你以前遇到过"答案明明一样却被判不一致"，这一版就是修它。

## 1.0.100：听力接线里有两处"替你说已核对"的地方

- 有听力音频时，工具会把切好的音频接进 HTML。这一版修掉两处会让页面**看起来像已经核对过**的地方：清单没写明切点是人工核对还是静音自动分段时，以前会替你写成"已核对"；现在不写这个默认值，并在报告里说明"边界核对责任不清"。
- 另一处更值得注意：**当整卷原音找不到时**，工具以前会随手把附近的转写文件挂到这一节上当作证据（如果那份转写连来源字段都没有，还会被当成同一段录音）。现在找不到就**不挂**，并告诉你原因（原音不在磁盘上 / 附近的转写都不是这段录音产生的），而不是拿一份可能不相关的转写充数。
- 另外，如果对齐数据里**没写**边界是怎么来的（`boundary`），构建会直接拦住并告诉你要补哪一项——因为页面只在写明"静音自动分段"时才标"边界待核对"，不写就等于让页面显示成已核对。
- 听力接进 HTML 的这条主路以前**一个自动测试都没有**，现已补 17 项（含"原音缺失不许猜转写""没声明就不许补已核对"等反向用例）。
- 你不需要做任何事；如果你是手写对齐数据的老用户，补上 `boundary` 即可。

## 1.0.99：听力对齐的报错以前会指错方向；顺手补上它缺失的测试

- 有听力原文时，工具会把原文对齐到**你已经核对过的时间窗**里。它的 `plan.json` 从没要求过 `verified` 这个字段，可报错却写着"请先完成切点核对（verified=true）再对齐"——**照这句话改不出任何结果**。现在报错说的是真实要求：先确认题组所在的时间窗，再按工作流文档写 `segments`。
- 计划文件写错时，以前会漏出英文的 Python 报错（`ERROR: 'start'`），或者干脆抛类型错误。现在会**逐项点名**："缺少 id/start/end/text""start/end 必须是秒数（数字）"。
- 这个对齐脚本以前**一个自动测试都没有**，而验证文档里却写着"它的校验与拒绝逻辑由自动测试覆盖"。这句话当时不成立，现在已经补上 12 项测试，并把那句旧记录改正了。
- 你不需要做任何事：对齐质量仍要你抽查，工具只保证不把异常时间当成"已完成"。

## 1.0.98：更新时不会再把技能"改成一半"

- 更新时会先备份、再替换文件。如果替换到一半失败（Windows 上很常见：文件正被 OneDrive/网盘同步、杀毒或 Office/WPS 打开着），以前会留下**一半新版、一半旧版**的技能目录，很难收拾。
- 现在：**动手前先逐个试探能不能写**，只要有一个文件写不进去就当场停下，并告诉你是哪个文件、被什么占用（**此时一个文件都没动**）；万一还是中途失败，会用备份**自动把改过的文件恢复回去**；如果连恢复也被占用挡住，会明确告诉你**哪些文件没能恢复、从备份哪里手动复制**，不会说"已经恢复好了"。
- 顺带把 Windows 下载文件常见的标记（`Zone.Identifier`）和盘符路径在解压阶段就拒掉，并说明原因。
- 你不需要做任何事；下一次更新会更安全。

## 1.0.97：照片文件夹里"原图"和"裁剪"混在一起时，会提醒你先分开

- 用手机拍卷子的老师常把照片分成"原图"和"裁剪"两个子文件夹。以前助手扫整个文件夹会**把两批都算成页**：一份两页的卷子会变成三页，顺序还乱掉——而检查却显示"没问题"，后面的转录和指纹就全跟着错了。
- 现在这种情况会被明确拦下，并告诉你两条路：只指向其中一批（例如"原图"），或者按页序把文件一个个列清楚。
- 顺带明确：系统文件（`.DS_Store`、`Thumbs.db`、`desktop.ini`）和说明文本不会被当成试卷页。
- 你不需要做任何事。

## 1.0.96：证据重听时，音频不会再因为播放器的请求方式而哑掉

- 上课时点"证据重听"跳到某一秒，靠的是一个只在本机运行的小服务。它以前**没有任何测试**，而且遇到某些播放器发出的"分段请求"会直接回一个错误——结果是**音频完全放不出来**，老师会以为文件坏了。
- 现在这类请求会被正常处理（照常返回整段音频），并且补了 12 项测试把这个服务的行为钉住：跳转切片精确、越界如实拒绝（避免"跳到某秒却从头播"）、路径安全、类型正确。
- 你不需要做任何事；这条影响的是课堂上的证据复听体验。

## 1.0.95：分节写作的"合并前体检"不再误报

- 卷子多、想多个人分头写时，助手会把整卷拆成"每节一个文件"，写完再合并——合并前有一道体检。以前这道体检要求"每一节都必须有原文段落"，于是**配对阅读、书面表达、只有题目的节**全被判成不合格：正常的卷子先报错，还可能逼着助手去编一段原文来"通过"。
- 现在体检只拦真正会让合并出事的：**题号在不同节里重复**（以前要到生成时才报）、某节还没有题号、没写题型名。"这节没有原文"改成了提示，并说明哪些题型本来就没有原文。
- 你不需要做任何事；这条影响的是助手分头写作时的流程。

## 1.0.94：选"只要听力"时不再卡在 A 这个字母上

- 你在第一个问题里回答 `A`（只做听力）时，助手有两种往下传的方式：一种会正确翻译成"听力"，另一种可能把 `A` 原样传给筛选命令——**初中卷会因此报"材料中没有这个板块：A"**（因为初中卷的小节编号是 S1、S2…，不叫 A）。
- 现在这个歧义被处理掉了：字母对得上小节编号就按编号走，对不上就按你的意思解释——`A`=只要听力、`B`=整卷、`C`=需要你说明具体板块。卷子里没有听力却选了 A，也会直接告诉你"这份卷没有听力节，整卷请用 all 或写板块名"，而不是一句看不懂的报错。
- 你不需要做任何事，继续用 A/B/C 回答即可。

## 1.0.93："图A/图B"不能再当选项交上来

- 有些题的选项是**图片**（比如听说里的"听句子选图"），卷面上只印 `A. 图A B. 图B C. 图C`。以前助手要是照抄这几个字，课件里学生就只看到"图A/图B/图C"，等于这道题没给图——而且**没有任何检查会拦**。
- 现在这种"只有图片占位、没有真实图片"的题会被**直接拦下**，并明确告诉助手两条路：把真实图片配成图片选项；确实拿不到图就标成待核、写进人工复核清单，不许用文字冒充。
- 判定很克制：只有"图/图片/图N"这种引用才算占位；像语法选择里选项本身就是 `a`、`an`、`the` 的，不会被误伤（这一条是我自己的回归测试先报出来的假阳性，已修正）。
- 骨架生成时也会提前提示"本节选项像图片占位"，助手在第一轮构建前就知道要配图。

## 1.0.92：初中"读写综合"里的书面表达，现在真按写作处理

- 初中卷常把阅读和写作合成一道大题："七、读写综合"，下面再分 `A. 回答问题` 和 `B. 书面表达`。以前程序只认大题名，认不出"读写综合"，于是**B 的作文被当成普通自定义内容**——不会给你写作工作区（审题、提纲、语言支架、范文示范），也不会提醒你补范文。
- 现在会看小标题：`B. 书面表达` → 按写作处理，`A. 回答问题` → 按阅读处理，`A. 听句子选图` → 按听力处理。认不出来的（例如"综合运用"）仍然不擅自归类，留给你和助手按原卷判断。
- 骨架里会把判断结果写出来（并在待办第一条提醒核对），所以助手一看就知道这节该按什么讲；不对可以直接改。

## 1.0.91：初中卷的骨架不再被切碎、分值不再丢

- 拿一份初三卷子（听说应用、语法选择、完形填空、阅读理解 A–C、配对阅读、短文填空、读写综合）做实测，发现三处会直接影响老师的地方：
  - **听说应用被拆成 6 段**：选项写成单独一行 `A. 图A B. 图B C. 图C` 时，被误当成"新的小节"。现在只有真正的 A./B. 小标题才会另起一节，选项行会正确拆成 A/B/C。
  - **阅读理解分值全丢**：卷面上"每小题 2 分、共 30 分"在出现 A/B/C 小标题后不再显示。现在每个小节会继承"每小题 2 分"，小节总分按"每小题 × 本题数"算出来（并明确标注"这是推算值，请对照原卷"）。
  - 同一行的 B/C/D 选项以前只留下第一个字母的内容，现在四个选项都在。
- 这份卷子修前是 15 个碎节、修后是 10 个正常节（题型名、板块、题数、分值全对）。你不需要做任何事，下一份卷子直接受益。

## 1.0.90：试卷里文本框的题干不会再出现两遍

- 有些试卷的题干/表头是放在**文本框**里的（Word、WPS 都很常见）。这类内容在文件内部会存**两份一模一样的副本**，以前助手会把两份都读出来——题干变成连着两遍，解析题号时也对不上。
- 现在**只读一份**，并且文本框里若有多段会按段分开；表格单元格里的文本框一样处理。读入的段落还会标一个"含文本框"的记号，提醒助手**位置顺序仍要对着原卷核对**（这一点没有假装自动搞定）。
- 你不需要做任何事；下一份带文本框的卷子就会正常。

## 1.0.89：答题卡式的答案表能直接用了

- 很多答案原件是**一张表**：上一行题号、下一行答案。以前这种表格助手解析不出来（只能读"每行 题号 答案"那种），最后要么手工录入、要么报"未识别"。现在这种表**直接解析**，也能分段（1–5 题一张、6–10 题一张），语法填空那种单词/短语答案同样支持。
- 安全起见**不猜**：如果题号行和答案行的列数对不上，会明确告诉你"题号 3 列、答案 2 列……不要按顺序硬对齐"，让你回原件核对；某个格子空着也只会点名那一题，不会把整张表作废。
- 这一版同时修正了文档里"表格版答案要全靠人工"的旧说法——现在是脚本解析、仍然要逐题与原件比对。

## 1.0.88：Windows 老师不用敲命令了

- 想让助手看到"这台电脑到底能做什么"，以前要你复制一条命令到终端。现在**双击技能包里的 `一键体检.bat`** 就行：它会自己跑完检查、把报告文件生成出来，并停住让你看路径。
- 它**不安装、不下载、不改任何设置**；报告里只有文本，**不含你的试卷和音频**，可以放心发回。
- 提醒一句：这个双击脚本的行尾与编码已按 Windows 要求做好并有测试守着，但我这边（macOS）**没法真正运行 Windows 命令**，所以结论仍要看你在真机上跑出的报告。

## 1.0.87：说明书标清了"哪部分不用读"

## 1.0.86：一次把问题说全

- 以前一份新卷子可能要让助手来回四趟：先报结构问题、再报缺哪些栏目、再报台账/来源对不上、最后才报答案追溯问题。现在**一趟就把四类问题全列出来**，老师少等三次，助手少花三轮额度。
- 如果结构还没修好、后面的台账条目是连带报出来的，会明确提示"先修结构，再按剩余条目核对"，避免去改不该改的地方。

## 1.0.85：让助手少读没用的部分（省额度）

- 助手以前每做一份卷子都要通读两份说明书（约 45KB + 25KB）。现在把**纯讲界面行为**的 8 节标成"写内容时可以跳过"（约占三分之一），并在字段说明顶部加了一页"这次要写哪些字段"的清单：读完这一页就能动手，其余只读和本次题型/功能相关的那几节。
- 你不需要做任何事——这条只影响助手读多少、写多快。检查要求一条没减：该写的字段一个都不能少，只是不用先读完全部说明。
- 说清代价：字段说明本身因为加了这页清单变长约 6KB；**只有按清单按需读才省**，通读反而更贵。所以真正省下的是"少读无关章节 + 第一次写对、少返工一轮"。

## 1.0.84：生成时少跑一轮

- **报错一次列全，扩大到"缺哪些栏目"**：以前一节课的栏目缺三项时，要先修完结构问题、重跑，才会冒出栏目的缺项清单——等于白等一轮。现在两段合成一条完整清单，看到的就是本次全部要改的东西。
- 这一条不改变任何检查要求，只是把"两次往返"变成"一次往返"：老师少等一轮，助手少花一轮额度。其余不变。

## 1.0.83：下不动整包时，一条命令就能把文件抓全

- 有些网络/平台既下不了整包、也克隆不了仓库，只能用"一个个文件抓"这条路。以前那是**一百多次手工请求**，少一个文件、或某个文件被截断，都会等到生成时才报错。
- 现在是一条命令（助手执行、你不用敲）：它会按清单把每个文件抓下来，并**逐个核对指纹**——缺文件、内容不符、清单里有越界路径，都会明确列出来，内容不符的文件不会留在磁盘上。
- 它**不会说"已经装好了"**：装没装上，只看 `check_install.py` 有没有到 `complete`。它也不会声称"来源已经可信"（文件和清单来自同一条通道，指纹一致只说明传输没坏）；要证明来源，仍要用官方 `SHA256SUMS.txt` 核对官方整包。

## 1.0.82：没有梯子时，多了一条真能走的路

- 装了没梯子/被平台限制时怎么把技能包弄到电脑上，现在有**四条路**，助手会按可靠性依次试，并用 `host_probe.py --network` 如实报出哪条通：
  1. **你把发布 ZIP 当附件发给助手**（最稳，约 2MB，微信/邮件都能转发）；
  2. 助手抓 `raw.githubusercontent.com` 上的文件；
  3. **新增**：第 2 条打不开时，改走 jsDelivr 的公开 CDN 抓同样的文件（第三方通道，通常更好打开）；
  4. 最后才是 `git clone`（沙箱常拦，失败不要反复重试）。
- 关于第 3 条要说实话：它保证的是"文件传过来没损坏"（哈希能对上），**不能证明来源没被篡改**；要证明来源，仍要用官方 Release 的 `SHA256SUMS.txt` 核对官方 ZIP。文档没有把它说成和 GitHub 一样可信。
- 顺带把"整包多大"写进 FAQ：**约 2MB**，所以"换一台能上网的设备（比如手机流量）下载，再用微信传过来"通常是最省事的办法。

## 1.0.81：没有梯子能装吗？助手说"沙盒限制"是什么？

- 这两件老师最常问的事，现在 [常见问题](FAQ.md) 里有直接答案：
  - **没有梯子通常也能装**：安装只要那台电脑/助手拿到完整 ZIP，**下载可以在别的地方完成**（手机流量、别的网络、同事电脑），再当附件发给助手。也说明了为什么"能打开 GitHub 网页"不等于"能下完整包"——看仓库、抓 `raw.githubusercontent.com`、下载 Release 的 ZIP 是三条不同的通道。
  - **"沙盒限制/网络受限"不是这个 Skill 的问题**，是 AI 助手所在平台给的执行隔离（网络白名单、只许写工作目录、不给执行脚本、预览限制脚本与媒体、云端容器不等于你的电脑）。文档给了一张"看到什么 → 怎么做"的表，并说明为什么"别人能装、我这台不行"通常是通道不同。
- 顺便给文档加了一条防断链检查（链接指向不存在的文件会直接失败），避免你顺着链接点到 404。

## 1.0.80：更新时能真正核对来源了

- 以前更新说明里写着"下载同版的校验清单 `SHA256SUMS.txt` 来核对压缩包指纹"，但**发布时根本没有产出这个文件**——这一步等于落空。现在打包会连同 ZIP 一起产出校验清单，助手就能真的核对"这个包是不是官方那一份"。

## 1.0.79：中文 Windows 更稳，路径写错时看得懂报错

- **中文 Windows（最常见的环境）专门回归**：以前只在英文 Windows 的编码下测过"中文会不会崩"，这一版补上**中文 Windows 的 cp936**（以及 gbk）三档实跑，确认检查、自检、功能菜单、成本估算、宿主探测都不崩、中文不乱码。

## 1.0.77：又快了一截，并把"时间花在哪"写清楚

- 构建里的**词库裁剪**（默认只内置本篇出现的词）原来要拿整本一万多条词库逐条比对，占了构建近三成时间；现在先做一次便宜的预筛再照原样确认，**结果一个字都不变**（有等价性测试守着）。这一项 32 节从 0.80 秒降到 0.24 秒。
- 顺手把整卷脚本链路的时间构成量清了（32 节 / 64 题）：**构建 0.68 秒、产物核验 0.01 秒、浏览器点击验收 45.7 秒**。也就是说，脚本侧真正耗时的是"在浏览器里逐节切换、逐题点开"的验收环节——它是交付前必须真点真播的那一步，我们**故意不抄近路**（正因为它是"构建通过 ≠ 按钮可用"的唯一证据）。

## 更省时间、更省额度

- 只做你选的范围；未选的功能不生成、不显示入口；
- 长引文可以只写字符范围，由脚本回填（不改教学内容）；
- 构建报错会**一次列全**并给出实际值（例如"实际出现 1 次，条目写的是 9"），照清单一次改完即可；
- 会报出"同一段内容写了两遍"和"疑似讲重复了"的清单（后者只提示，判断仍在你）。

## 交付更严格（对你有好处）

- 没做浏览器点击验收、没写人工复核清单，就**不允许打包**（只能交"待验收版"）；
- 报告里"跳过的检查"会明确写成未验证，不会被算作通过；
- 内容不许编：引文必须逐字出自原文、生词必须真的出现在本篇、文化背景必须有可核对来源、听力挖空必须落在真实词语上。

## 已知限制（这一版做不到的）

这几条是边界，不是故障；遇到时不用反复重试，按右列处理即可。

| 你想要的 | 这一版的实际做法 |
| --- | --- |
| 把一张跨页照片自动切成两页 | 只登记"几张照片共几页"并提醒按左右页逐页核对；要真的切图，用系统截图/裁剪工具手动裁 |
| 点图片选项里的词查词 | 图片选项没有文字可点，只能看；**文字**选项才支持点词带读与语境义 |
| 同一大题里 1 分题、2 分题分别标分 | 每节只标一档"每小题 X 分"（取试卷标题）；混排时写主档，页面不逐题标分 |
| Word/WPS 文本框的位置顺序 | 文本框里的字会去重后并进所在段落（不再出现"同一题两遍"），但**顺序**仍要对照原件；照片里的字同样要人工核对 |
| 没有 ffmpeg / whisper 也能自动切听力 | 缺 ffmpeg 测不了时长也切不了；缺 whisper 只给"静音候选"，题与题的边界仍要人工确认 |
