# 宿主能力与回退

这份文档在**开工前**读。同一个 Skill 在不同宿主里跑，能力差别很大：有的能读整个技能包、执行脚本、开浏览器；有的只能看聊天里粘贴的文字。差异本身不是错误，**把不确定的能力说成已经具备**才是错误。

探测能力的目的是如实报告边界，不是给这套 Skill 减功能。基础讲评、答案溯源、听力播放和备课编辑是交付基线，不因为某个可选扩展不可用就消失；确实做不了的环节要说清是哪一步被挡住，而不是换一份更简单的东西冒充完成。

## 一、能力维度

| 能力 | 为什么需要 | 缺失时的典型表现 | 正确做法 |
| --- | --- | --- | --- |
| 读取完整技能包 | 需要 `assets/` 模板、`scripts/` 脚本、`references/` 规则一起在磁盘上 | 只看到粘贴的 `SKILL.md` 文字，找不到模板和脚本 | 说明只能读到文字，未完整安装；不能凭文字生成"同款"课件 |
| 读取老师附件 | 试卷 PDF/DOCX/图片、答案、听力音频是全部内容的来源 | 只收到文字描述或文件名，读不到内容 | 追问缺失的具体文件；不按常识补写原题 |
| 写入文件 | `build.py` 要输出 `index.html`、媒体、报告与 ZIP | 只能把结果贴在对话里 | 说明无法落盘；不把一段 HTML 源码当成品 |
| 执行 Python | 构建、校验、审计、打包都由 `scripts/` 完成 | `python3` 不存在或被宿主禁止 | 指明被挡住的是构建/验收哪一步，不用手写网页替代 |
| 真正的多选控件 | 功能选择要一次拿到七项的真实勾选 | 只有一个"确认/取消"或单选 | 改用编号清单，请老师回复多个编号；**不能用单选冒充多选** |
| 真实浏览器操作 | 点击、显答、切节、播放、变速必须实际操作过 | 只能看到静态截图或 HTML 文本 | 只交付标注"待浏览器验收"的版本，不写"已通过点击验收" |
| 下载官方包/FFmpeg/模型 | 完整安装与听力分段依赖外部下载 | 只能访问部分网页，无法取得完整 ZIP/二进制 | 报告"完整包下载受限，尚未完整安装"；不拼文字文件夹、不交 `.sh` 安装脚本冒充完成 |
| 跨轮持久保存文件 | 生成是多轮的，工作目录要能延续 | 下一轮看不到上一轮写出的文件 | 请老师把技能包与产出放在一起保留；不假设上一轮路径仍然存在 |

## 二、宿主速查

以下按"通常具备 / 不确定（以当前实例实测为准）/ 缺失时"三栏描述。**这是先验判断，不是实机认证**：本项目已在 Codex 本地环境完成整卷制作与验证，WorkBuddy 曾完成真实生成但整卷链路仍需复测，豆包工作尚未完成整卷实机验收，其他宿主同理。

### WorkBuddy

- 通常具备：读取本地技能包、读写工作目录文件。
- 不确定：能否执行脚本（历史上有过真实生成，但仍需按当前实例实测）、长期运行是否有超时、内置预览是否限制脚本/媒体/弹窗/下载、浏览器自动化工具是否可用。
- 缺失时：预览打不开就下载完整 ZIP、解压后用系统 Chrome/Edge 打开；不要为了绕开预览限制重写正确模板。没有浏览器工具时按待验收版交付。

### 豆包工作（Doubao Work）

- 通常具备：对话式交互、读取上传的附件、按工作任务模式执行多步流程。
- 不确定：能否读取整个技能目录（而不只是单个文件）、能否执行 Python、能否把产出作为可下载 ZIP 交回、内置预览是否运行脚本。
- 缺失时：先在回复里明确"当前环境无法运行脚本/无法读取完整技能包"，只做能做的部分（例如识别材料、写解析），不输出一段 HTML 就宣称生成完成。不编造技能导入菜单。

### Codex 风格本地编程 Agent

- 通常具备：完整读写文件、执行 Python 与 shell、在本机目录里持续工作。
- 不确定：是否装有 Node + Playwright 或可用的浏览器工具、网络是否允许下载 FFmpeg/模型、是否有跨轮持久工作目录。
- 缺失时：有 Playwright 就跑 `node scripts/browser_check.cjs OUTPUT --stress`；没有就用宿主浏览器工具逐项操作；连浏览器都没有就交付明确的待验收版，不无限下载安装。依赖下载失败按 [依赖失败与有界恢复](dependency-recovery.md) 处理，不静默降级精听。

### Claude 风格 Agent

- 通常具备：强文字处理、能读取对话中提供的材料并编写解析。
- 不确定：是否真的挂载了本机文件系统、是否允许执行脚本、是否有浏览器工具、输出能否保存为可下载文件。云端会话的路径不是老师电脑上的路径。
- 缺失时：先确认文件与执行能力再开工。只能读文字时，可以产出讲解草稿，但不能声称已生成可上课的同款课件，也不要把云端临时路径当成交付。

### 纯聊天窗口

- 通常具备：文字问答，能根据粘贴的试卷文本写解析。
- 不确定：几乎全部工程能力（读写文件、Python、浏览器、下载）通常都不具备。
- 缺失时：如实说明"这不是完整生成环境"。可以帮老师整理题目与讲解思路，但没有完整技能包、不能构建和验收时，不交付 HTML 成品，不写"已生成可上课课件"。

## 三、缺失能力时的统一回退

按项目既有标准执行，不因宿主不同而放宽：

1. **没有真正的多选控件** → 用编号清单一次列出七项功能，请老师回复多个编号（例如"1、2、5"），也接受"全部/都不要/沿用上次"。**禁止用单选冒充多选**，也禁止逐项问七轮。未回答保持待确认，不开始生成。清单与计划转换直接跑 `python3 scripts/plan.py menu` 与 `python3 scripts/plan.py make --confirmed --range ... --features ...`，不要手写 JSON（手写容易漏项，构建会以“请记录全部可选功能的选择”阻断）。
2. **没有浏览器** → 只交付明确标注的**待验收版**：打包时用 `python3 scripts/package_lesson.py OUTPUT LESSON.zip --allow-unchecked`，状态写 `preview_only_browser_check_pending`，并在交付说明里用中文写"待浏览器操作验收"。**不得**写"已通过点击/播放验收"，不得手写 `browser-check.json` 通过状态。qa-report 的浏览器一节仍要写实际做了什么（哪怕只是"未执行"）。
3. **不能执行 Python** → 说明被挡住的具体阶段（模板校验、构建、答案审计、音频裁剪、打包中的哪几步），把已完成的部分与未完成的部分分开列。**不得**只贴一段 HTML 代码就当作交付完成。
4. **不能下载完整包** → 报告**"完整包下载受限，尚未完整安装"**。**不得**从网页片段拼一个不完整目录，**不得**只给一个待运行的 `.sh` 脚本当作"已安装/已更新"。
   - `python3 scripts/host_probe.py --network` 会按可靠性排好四条安装路径并如实标注可用性：`teacher_uploaded_zip`（最稳；没确实拿到附件就写 unknown，不能猜）→ `raw_files_fetch`（抓 raw.githubusercontent.com）→ `cdn_jsdelivr`（raw 打不开时的第三方 CDN 备选）→ `git_clone`；探测只发 HEAD 请求、不下载不改动，没加 --network 时如实写 `not_probed`。第 ②③ 条都用 `scripts/fetch_package.py --base <url> --out <目录>` 一条命令抓（按清单逐个下载并核对 SHA256，拒绝越界路径）；它是**第三方通道**，抓完必须 `check_install.py` 到 `complete`，且不能声称来源已证明。
   - 实测过的一种情形：宿主沙箱拦住 `git clone github.com`（TLS 握手失败），但网页抓取可用。**优先让老师把发布 ZIP 作为附件上传**，直接解压安装；其次是逐个抓取 `raw.githubusercontent.com` 上的文件（抓完必须跑 `check_install.py`，不完整就如实说）。任何情况下都不要在没跑通 `check_install=complete` 之前说"已安装"。
5. **不能跨轮保存文件** → 明确告诉老师：请把 Skill 包、原始材料与已生成产物放在同一处保留；下一轮开始时先重新确认实际存在哪些文件，不假设之前的路径还在。
6. **不能读取附件内容** → 追问缺失的具体文件（哪一页、哪份答案、哪段音频）；资料确实读不到时保留未知，**不按常识补写原题或标准答案**。

## 四、开工前的探测清单

先做下面几件事，再决定这次能交付到什么程度。命令里的相对路径以技能包根目录为准；Windows 用可用的 `py -3` 或 `python`，macOS/Linux 用 `python3`。

最省事的是先跑一条命令，它一次性报告读包 / 写文件 / 执行 Python / Node / Playwright / 浏览器 / ffmpeg / whisper 的实际结果，并给出推荐的交付级别：

```bash
python3 scripts/host_probe.py --json
```

要把"这台宿主实际能走到哪一步"一次性留档并发回时，跑 `scripts/smoke_report.py`：它按顺序执行安装完整性、宿主能力、示例构建、模板核验、浏览器点击与打包，写出 `smoke-report.json` 与 `smoke-report.md`；不安装、不下载。跳过浏览器验收用 `--no-browser`。

它只探测本机，不安装、不下载、不改文件。下面几项是它在测什么，以及仍需人工确认的部分。

1. **安装完整性**
   ```bash
   python3 scripts/check_install.py
   ```
   - `status=complete`：核心文件与哈希齐全，可以继续。
   - `status=incomplete_install`：缺模板、词典、脚本或哈希不符。**不能宣布"已安装/已更新/可以生成"**，先按 [安装与更新](../docs/UPDATE.md) 处理；只看过 README 或 VERSION 不算安装完成。
2. **本机工具链与听力档位**
   ```bash
   python3 scripts/doctor.py --json
   ```
   - 输出里的 `installation.status` 不是 `complete` 时，doctor 会先停下并只报告安装问题：先补齐安装，别继续读能力字段。
   - `capability=full_auto`：ffmpeg/ffprobe 与可用转写模型都在，可走完整自动分段。
   - `capability=silence_only`：只有 ffmpeg，没有可用转写；可走静音分段，但边界要标"待核对"。
   - `capability=no_ffmpeg`：连 ffmpeg 都没有；接入整卷原音并标注"未分段"，或按依赖恢复文档在授权范围内准备。
   - 同时看 `pdf_tools`：没有 PDF/OCR 工具时，扫描卷要靠宿主的视觉识别能力，DOCX 仍可用 `scripts/extract.py`。
3. **本宿主自身的四项确认**（逐条实测，不要凭猜测）
   - 能列出技能包目录并读到 `assets/lesson.html` 与 `scripts/build.py` 吗？→ 否则视为"只能读文字"。
   - 能写一个临时文件并读回吗？→ 否则构建产物无法落盘。
   - 能运行 `python3 -c "print(1)"` 吗？→ 否则构建、审计、打包都不可用。
   - 有浏览器工具或 Node + Playwright 吗？→ 否则最终只能交付待验收版。

## 五、能力探测不等于关掉 Skill

- 可选扩展（批注、查词、课堂工具、篇章精读、写作迁移、文化背景）按老师的选择启停；缺工具只影响对应的扩展或增强环节。
- **基础讲评、答案原件溯源、听力播放、备课编辑与课堂记录导出属于交付基线**，不因宿主缺少某个扩展能力而被删掉或改弱。
- 宿主缺少某项能力时，正确结果是"这一步没有完成，原因如下、替代路径如下"，而不是把整个流程悄悄换成一段简化网页或只含部分题型的版本。
- 页面与报告里的状态词要如实填写（例如 `preview_only_browser_check_pending`、`audio_delivery.mode`、听力边界 `verified` 与否），不用模糊说法掩盖未完成项。

## 六、汇报时要写清的三件事

1. **这次实际具备哪些能力**（读包、读附件、写文件、执行 Python、多选控件、浏览器、下载、跨轮保存），逐项写"是/否/未测"。
2. **哪些环节因此没有做**，以及老师可以怎么补齐（换环境、下载到系统浏览器、提供已下载的便携工具、只看待验收版）。
3. **交付物到底是什么状态**：完整安装与否、构建是否通过、浏览器是否实测、听力是哪一档、答案溯源到哪一层。三者是独立结论，不能互相代替。
