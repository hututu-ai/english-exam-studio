# 本篇文化背景：从原文进入，再回到理解

仅在老师勾选 culture_background 后读取并执行。目标是帮助学生理解本篇背后的人、社会与文化，不是百科卡片、全文翻译或通用主题知识。

## 生成流程

1. 通读本篇，寻找需要背景才能理解的人物行为、社会制度、历史事件、生活习俗、流行文化典故、价值观或文化表达。记录实际段落与完整、有意义的原文引句；不能只摘无信息的开头几个词。
2. 对每个候选问：不了解它，学生会误解什么或遗漏哪一层意思？若无法回答，舍弃。不要每段配一条，也不要求每篇凑固定数量。科学概念本身不自动等于文化背景。
3. 查阅与候选直接相关的可靠资料，优先博物馆、文化机构、原始研究、官方档案等。逐条说明来源支持什么事实；搜索摘要、项目主页或不相关链接不能证明事实。不能核实时删掉该项并说明原因，不编造来源。
4. 写成三层：原文切入 → 背景解读 → 回到本篇的理解。背景解释原因、形成过程或社会意义；回到本篇须说明具体人物动机、作者选材、幽默、语气、对比或主题如何因此更清楚。不要只写“有助于理解文章”。
5. teaching_note 写老师可直接讲给学生听的简明说明，必要时用贴近学生的类比；不是布置额外调查任务。区分原文明确内容、来源证实背景与解释性推断。文化背景不能替代原文答案证据，不概括某民族或国家的人“都怎样”。
6. 逐条人工语义复核相关性、来源支持和讲解深度，在 qa-report.md 记录结论（`qa_report.py init` 会把待复核条目列出，`check` 拒绝空结论）。结构校验通过只证明字段与引用合规，不代表背景已查证或教学质量合格。

## 数据合同

culture_background 每项包含：
- title：具体背景主题，避免“文化拓展”等空标题。
- paragraph_id、quote：来自本篇的逐字引句。
- explanation：已查证的背景解读，交代是什么及为什么。
- reading_connection：明确回到本篇，解释哪一处表达或意义；与 explanation 不重复。
- teaching_note：教师可直接使用的课堂讲述。
- sources：每项 title、url、supports；supports 指明该来源支持的具体背景事实。

本篇没有必要背景，或资料不足时用 culture_note 说明实际原因，不填空卡。所有正式内容禁止测试占位语。旧数据缺 reading_connection 或 sources.supports 时必须补充，不能复制旧字段自动糊过校验。

## 选材判断示例（不是可直接当事实复制的知识卡）

若开篇借 Lassie 与 Garfield 对比动物行为，应核实角色在大众文化中的形象，解释作者如何利用读者已有印象引入研究，以及研究如何修正印象。不要凭作品形象断言真实物种性格。

若文章出现传统乐器，应核实它与当地生活、仪式和文化传承的联系，再解释文中“某个民族的声音”等表达；不要只列起源年代，也不能把传说写成已证实历史。

若故事涉及录取信与校园参观，只有在资料和原文允许的范围解释这些实践，不能凭人名推断故事发生在哪个国家。
